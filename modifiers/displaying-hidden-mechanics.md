# Problem

Pure variables have **no default UI**. Players cannot see Purpose 60/100 unless you surface it.

# Solution (two layers)

1. **Score readout modifier** — 101 generated variants (`teu_nc_purpose_readout_N`) with static name `Purpose: N/100 (Tier)`. Monthly pulse calls `teu_nc_refresh_purpose_readout` to remove the old variant and add the one matching `teu_nc_order_purpose`. Generated by `tools/generate_purpose_readout.py`.
2. **Tier gameplay modifier** (`teu_nc_purpose_questioned`, `teu_nc_purpose_crisis`, `teu_nc_purpose_zealous`) — real penalties/bonuses when applicable.

# Modifier name vs description (KI-012/KI-015)

**Do not** use dynamic loc (`ROOT.*`, `GetPlayer.*`, `ROOT.Custom`) in `STATIC_MODIFIER_NAME_*` or `STATIC_MODIFIER_DESC_*` for live variable values — all fail silently or show errors.

| Field | Approach |
|-------|----------|
| `STATIC_MODIFIER_NAME_*` | Static string per score bucket (readout-swap), or fully static prose |
| `STATIC_MODIFIER_DESC_*` | Static guide text; score lives in the **name** via readout swap |

Tier label is part of the readout name (`Purpose: 62/100 (Steadfast)`).

# No dummy stats (KI-014)

A display-only modifier does **not** need a stat to appear in the country modifier list. A dummy stat like `monthly_prestige = 0.001` renders as an ugly `Monthly prestige = +0.00` line. Vanilla precedent for stat-less modifiers: `hre_internal_peace_enforced` (only `game_data = { category = country }`).

# Refresh strategy

In monthly pulse, `remove_country_modifier` then `add_country_modifier` for current tier so the list stays in sync.

# Tooltip content

Put the **monthly delta** and guide text in `STATIC_MODIFIER_DESC_*` — see [dynamic text](/localization/dynamic-text-in-loc.md).
